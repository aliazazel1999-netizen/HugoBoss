# ربات دانلود rule34.xxx برای تلگرام (Serverless روی Vercel)

ربات تلگرامی نیمه‌خودکار: با زبان طبیعی فارسی (هوش مصنوعی Gemini) به آن می‌گویید چه چیزی بخواهد، از rule34.xxx می‌گیرد و با کپشن ساختارمند به کانال/گروه شما ارسال می‌کند.

## امکانات

- **زبان طبیعی فارسی** با Gemini: «۵ تا عکس کاسومی با بالاترین امتیاز بفرست»
- **کیفیت اصلی عکس**: عکس‌های بزرگ‌تر از `PHOTO_MAX_MB` (پیش‌فرض ۲MB) به‌صورت فایل ارسال می‌شوند تا پیکسل دست‌نخورده بماند (تلگرام sendPhoto را همیشه فشرده می‌کند)
- **کپشن ۴ حالته** با دسته‌بندی هوشمند تگ‌ها (آرتیست / فرنچایز / شخصیت / عمومی) با کش Redis + AI + API سایت
- **زنجیره مدل‌های Gemini** با failover خودکار روی 404/429/500/503
- **ادامه خودکار صف**: اگر پس از آخرین ارسال چیزی مانده باشد، حدود ۵ دقیقه بعد خودکار ادامه می‌دهد (`/auto on|off`)
- **لینک پست** قابل خاموش/روشن (`/link on|off`، پیش‌فرض خاموش)
- ویدیو با تایم و تامبنیل، ضد تکرار، قفل اجرا، توضیح خودکار خطاها به فارسی

## فایل‌ها

```
api/
  webhook.js   دریافت آپدیت‌های تلگرام (پاسخ سریع 200 + پردازش در پس‌زمینه)
  cron.js      اجرای صف / انتظار ادامه خودکار / زنجیره خودفراخوان
  setup.js     ست کردن وب‌هوک و دستورها (بعد از هر دیپلوی/تغییر دامنه یک‌بار صدا بزنید)
  debug.js     تست کامل سلامت همه اجزا
lib/
  config.js    متغیرهای محیطی و کلیدهای Redis
  http.js      fetch با تایم‌اوت و User-Agent
  store.js     Upstash Redis REST (صف، ضده تکرار، قفل، پیکربندی)
  rule34.js    API سایت (جستجوی پست + تگ‌ها با پارسر JSON/XML دو-فرمتی)
  telegram.js  فراخوانی Bot API + ارسال بافر با تامبنیل
  gemini.js    زنجیره مدل‌ها، تفسیر دستور، دسته‌بندی تگ، توضیح خطا
  queue.js     کپشن ۴ حالته، ارسال هوشمند، اجرای صف، ادامه خودکار
```

## راه‌اندازی

۱. این ریپو را در گیت‌هاب خود پوش کنید.
۲. در Vercel → **Add New → Project** → ریپو را ایمپورت کنید.
۳. در **Settings → Environment Variables** همه متغیرهای `.env.example` را اضافه کنید.
۴. دیپلوی بگیرید، سپس یک‌بار باز کنید:
   `https://<دامنه-پروژه>/api/setup?key=<CRON_SECRET>`
۵. برای تست کامل: `https://<دامنه-پروژه>/api/debug?key=<CRON_SECRET>`

> دامنه پیش‌فرض هر پروژه ورسل: `<نام-پروژه>.vercel.app`

## مهاجرت بعد از ساسپند شدن اکانت گیت‌هاب (ربات بی‌پاسخ شد)

وقتی اکانت گیت‌هاب ساسپند می‌شود و اتصال Vercel↔GitHub قطع/عوض می‌شود، ربات معمولاً به دو دلیل بی‌پاسخ می‌شود:
**الف)** پروژه جدید ساخته شده و **متغیرهای محیطی از بین رفته‌اند** (envها به پروژه وصل‌اند نه به اکانت).
**ب)** دامنه پروژه عوض شده ولی **وب‌هوک تلگرام هنوز به دامنه قبلی اشاره می‌کند**.

به همین ترتیب رفع کنید:

### گام ۱ — کد را به اکانت جدید ببرید
```
git remote remove origin
git remote add origin https://github.com/<اکانت-جدید>/<ریپو>.git
git push -u origin main
```
(یا در Vercel خود پروژه را مستقیم از ریپو جدید ایمپورت کنید — کد کاملاً همین پوشه است.)

### گام ۲ — در Vercel اتصال گیت‌هاب را با اکانت جدید برقرار کنید
Vercel → Settings → **Git** → دکمه Disconnect (اگر اتصال قدیمی مانده) → سپس Connect و ورود با اکانت جدید.
اگر پروژه قبلاً ساخته شده و فقط اتصالش قطع شده، نیازی به پروژه جدید نیست؛ اگر پروژه جدید ساخته‌اید، از گام ۳ متغیرها را تنظیم کنید.

### گام ۳ — متغیرهای محیطی را دوباره وارد کنید
Project → Settings → **Environment Variables** — همه این‌ها با همان مقادیر قبلی:

| متغیر | توضیح |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات (از @BotFather — همان قبلی قابل استفاده است) |
| `ADMIN_ID` | شناسه عددی شما |
| `GEMINI_API_KEY` | کلید Gemini |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | همان قبلی (داده‌ها و کلیدهای کش سرجای خودشان هستند) |
| `CRON_SECRET` | همان قبلی |
| `WEBHOOK_SECRET` | همان قبلی |

سپس **Deploy → Redeploy** بزنید تا با envهای جدید بالا بیاید.

### گام ۴ — وب‌هوک را دوباره ست کنید (مهم‌ترین گام)
دامنه جدید پروژه را ببینید (Settings → Domains؛ احتمالاً `<نام-جدید>.vercel.app` شده) و این را باز کنید:
```
https://<دامنه-جدید>/api/setup?key=<CRON_SECRET>
```
پاسخ باید `"ok":true` و آدرس وب‌هوک با دامنه جدید باشد.

### گام ۵ — تست
```
https://<دامنه-جدید>/api/debug?key=<CRON_SECRET>
```
همه بخش‌ها باید `ok: true` باشند. سپس در تلگرام به ربات `/status` بدهید.

### اگر باز هم پاسخ نداد — اول `/api/doctor`، بعد جدول

**مهم‌ترین ابزار عیب‌یابی:** endpoint مستقل `api/doctor.js` هیچ import استاتیک ندارد، پس حتی وقتی بقیه کد کرش می‌کند هم بالا می‌آید و **علت دقیق ۵۰۰ را در مرورگر نشان می‌دهد**:
```
https://<دامنه>/api/doctor?key=<CRON_SECRET>
```
- بخش `modules` نشان می‌دهد کدام فایل لود نشده و **متن دقیق خطا** چیست (مثلاً `Cannot find module '../lib/config.js'`)
- بخش `diagnosis` علت رایج و راه‌حل را می‌گوید

علت‌های کلاسیک ارور ۵۰۰ بعد از جابه‌جایی ریپو:
| متن خطا در doctor | علت | راه‌حل |
|---|---|---|
| `Cannot find package "@vercel/functions"` | package.json ناقص/آپلود نشده | فایل package.json را برگردانید و ری‌دپلوی کنید |
| `Cannot find module '../lib/config.js'` | ساختار پوشه‌ها خراب شده (آپلود با وب گیت‌هاب فولدرها را فلت می‌کند) | با `git push` آپلود کنید، نه درگ‌ودراپ وب |
| `Cannot use import statement outside a module` | `"type":"module"` در package.json نیست | package.json را برگردانید |
| `SyntaxError` | فایل ناقص یا پسوند `.txt` | فایل را از نسخه سالم جایگزین کنید |

جدول عیب‌یابی `/api/debug` (وقتی همه ماژول‌ها سالم‌اند):

| نشانه در `/api/debug` | معنی | راه‌حل |
|---|---|---|
| `webhook.url` خالی | وب‌هوک ست نیست | `/api/setup?key=…` را صدا بزنید |
| `lastError: 500` | کرش استارتاپ (معمولاً import جاافتاده) | خروجی `/api/doctor` را ببینید |
| `lastError: 401/Unauthorized` | مغایرت `WEBHOOK_SECRET` | مقدار env و setup را دوباره انجام دهید |
| `redis.ok: false` | env آپ‌استش وارد نشده | گام ۳ |
| `bot.ok: false` | توکن ربات | توکن را دوباره از BotFather چک کنید |
| همه ok ولی ربات ساکت | آپدیت‌های معلق | `/api/setup` با `drop_pending_updates` آن‌ها را پاک می‌کند |

## نکته‌های مهم

- پس از **هر تغییر دامنه یا ری‌دپلوی نام پروژه**، یک‌بار `/api/setup?key=…` را صدا بزنید.
- `@vercel/functions` در `package.json` حیاتی است؛ نبودنش همه endpointها را ۵۰۰ می‌کند.
- پلن رایگان ورسل: cron فقط روزانه اجرا می‌شود؛ ارسال صف عمدتاً با زنجیره و ادامه خودکار انجام می‌شود.
